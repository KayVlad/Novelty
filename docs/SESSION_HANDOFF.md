## Architecture and recovery boundaries

Library schema 2, migrated without changing original game records. Close old UI processes before using this build. `src/launch.cpp` owns command construction/supervision (extracted from core.cpp); `src/setup.cpp` owns completion/retry; `src/runtime.cpp` owns process tracking; `src/removal.cpp` owns durable staging/removal recovery; `src/folder_import.cpp` owns manual folder move/import and its journal recovery; `src/installation.cpp` owns new installer allocation/detection; `src/diagnostics.cpp` assembles the bounded local report. Pending removal, interrupted folder import and completed-install detection recovery run in the discovery worker on startup/Rescan. A killed headless caller can recover same-boot while its monitor survives; a killed monitor or legacy marker still needs reboot. Steam full removal remains blocked due to untracked lifecycle.

`src/provisioning.cpp` runs installer helpers asynchronously. Helpers ship under `share/novelty` on install. GE uses an owned resumable workspace (restart download/extraction, no byte-range resume); umu uses small temporary staging and cooperative cancellation. A hard kill during umu publication can leave a small hidden staging directory for inspection; it is not broadly swept. Installer power-loss durability is not a tested guarantee. The umu pin lives in `scripts/install-umu.py` and `managedUmuPath()` in core.cpp; update them together when deliberately changing the supported pin.
